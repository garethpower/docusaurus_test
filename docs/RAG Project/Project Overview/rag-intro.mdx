# RAG Project Intro

Retrieval-Augmented Generation (RAG) is a technique designed to address a couple of limitations inherent to Large Language Models (LLMs):

* The knowledge a model was trained on has a **cut-off date**. This means that when a user asks a question the model may base its answer on information that is out of date. 
* The LLM **may not contain the specific knowledge** that the user wants to ask about.

RAG enhances the capability of an LLM by providing it with access to a specific knowledge domain not contained in its training data. 

When the user asks a question relating to that knowledge domain, the RAG system draws additional context automatically from a purpose-built database containing the specialised knowledge, and then sends the question to the LLM along with the context. This enables the LLM to answer the question with useful, accurate information.

## Project Objectives

In this project, I investigated the effectiveness of a RAG system for answering questions focused on a tightly defined knowledge domain. 

I tested various source formats and vary certain parameters to see whether this has a significant impact on the RAG system’s effectiveness. 



1.	Implement a simple prototype chatbot that uses a RAG system to query a specific, well-understood set of content.
2.	Understand how the choice of source content format affects the chatbot.
3.	Understand how chunking and overlap configuration affects the chatbot.
4.	Understand what kinds of issues can cause a chatbot to perform poorly.

## Outline of Solution

1.	Implement a RAG system populated with the relevant body of knowledge.
2.	Include sufficient logging and reporting capability to be able to understand the RAG’s workings for each answer.
3.	Run a standard set of questions through the chatbot for different RAG source formats and chunk size/overlap parameters.
4.	Score the chatbot’s answers, tabulate the results and present appropriate visualisations. 
5.	Analyse the results to measure the effectiveness of the chatbot for each configuration.
6.	Assess which configurations are optimal and which are deficient.
